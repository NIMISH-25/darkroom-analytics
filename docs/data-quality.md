# Data quality: planted problems and how the system handles them

Every problem below was checked against the real files in `data/synthetic/` (`batch_1`, `batch_2`, `golden_cases/*`). Messages and issue codes are copied from `backend/app/ingestion/parsers.py`, `batch.py` and `silver.py`. Row numbers below are 0-based positions in the JSON list, or spreadsheet row numbers for xlsx files. The parser's own error messages count records from 1. Ingestion behaviour was read from code; I did not re-run ingestion for this document, so exact CLI output lines are not verified.

## How a problem can be handled

| Outcome | Meaning | Where you see it |
|---|---|---|
| **Rejected** | The file is unreadable or breaks a hard rule. Nothing from it is loaded. The batch continues. | CLI prints `[Rejected] <path>: <error>` and exits 1. Data Health tab: "Failed files" table. Ingest run shows `files_failed`. |
| **Quarantined** | The file is readable but looks wrong (unknown header, overlapping week). Nothing from it is loaded. | CLI prints `[Quarantined] <path>: <error>`. Data Health: failed files, and the source badge turns orange "incomplete". |
| **Missing** | The manifest lists the file but it is not on disk. | CLI prints `[Missing] ...`. Source badge rose "missing". |
| **Ignored** | The file is on disk but not in the manifest. | `unlisted_file` quality issue (warn). |
| **Accepted with an issue** | Rows load, but a `meta.quality_issue` row records the problem (severity `info`, `warn` or `suspect`). | Data Health "Unresolved identities" and open-issue count; evidence sheets list exclusions and warnings. |
| **Handled silently by design** | A normal rule, no issue (for example duplicates collapse onto one key). | Nothing to see; numbers are correct. |

Status badges (Data Health, KPI strips): `current` emerald, `stale` amber, `incomplete`/`partial`/`suspect` orange, `missing`/`unavailable` rose. A value that depends on a bad or missing source is `null` and shows "Unknown" with a reason, never 0.

## Problems in the golden fixtures (`data/synthetic/golden_cases/`)

These are tiny sets with hand-written answers (`tests/golden/expected.yaml`).

| Fixture | Problem |
|---|---|
| `batch_1` | A duplicated order and affiliate record on a "page 2" file; a sample order (all "0.00"); a missing weekly video; an Excel serial delivered date; unknown sample creator `cr_9999`. |
| `batch_2` | A $20 late refund; order `O_G2` at 2026-10-31 23:30 PT; header drift in four W42 files; crunchwell order `O_C1` corrected from $30.00 to $45.00. |
| `batch_3` | A **EUR order** `O_T2` (`payment.currency` "EUR", sub_total "100.00") in `orders/threadline/2026-09.json`, row 1; partial refunds; a look-alike creator handle; a stable-id handle change; a roster with a 60/40 split and a missing split. |
| `batch_4_revision` | One $1.00 verdant order: changes only the data revision. |
| `batch_older` | An older version of crunchwell order `O_C1` (older `update_time`): must lose to the newer version. |
| `batch_bad` | Verdant order file missing `order_id` (rejected) beside a good returns file (accepted). |
| `batch_overlap` | Aurelle W41 resent with different numbers (quarantined). |

**EUR order handling (golden fixture only; the synthetic batch_1 and batch_2 contain no non-USD order):** an order whose currency is not USD is excluded from USD GMV. The original amount and currency are stored. Raises `currency_mismatch` (warn) with message `currency EUR`. The evidence sheet lists the exclusion with reason `non_usd_currency`. No conversion is attempted (see `docs/rulings-after-verification.md`).

## All quality issue codes

Written by Silver build (`silver.py`): `version_conflict`, `creator_unresolved`, `creator_ambiguous`, `creator_not_on_roster`, `unknown_shop`, `currency_mismatch`, `duplicate_line`, `bad_amount`, `negative_amount`, `orphan_attribution`, `bad_commission_status`, `refund_missing_completed_time`, `bad_return_status`, `orphan_refund`, `refund_exceeds_paid`, `contract_conflict`, `unknown_allocation`, `allocation_sum`, `duplicate_row`, `bad_post_time`, `bad_date`, `bad_month`.
Written by file handling (`batch.py`): `file_rejected` (error), `file_quarantined` (warn), `file_missing` (error), `unknown_extra_column`, `unlisted_file`.

Not verified: that every code above fires on the planted data. Rows 1-21 were located in the files by script; the messages come from reading the code.
